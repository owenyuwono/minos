# enki — agent guide

enki is a Rust + Vulkan (via `ash`) renderer for a **procedural cube-sphere planet**, with a
custom RHI and an **on-demand voxel (transvoxel) terrain path** (the default). A Nanite-style
virtualized-geometry path and the classic quadtree mesher are the alternate, feature-gated paths.

## Build / run

`cargo` is **not on PATH**. In PowerShell prefix with:
```
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
```
- Run: `cargo run -p enki-app`
- Check/build: `cargo check -p enki-app` (use `check`, not `build`, while the app is running — the `.exe` is locked).
- Default features = `flora,voxel` (voxel terrain + planet flora). **Nanite is opt-in**: `cargo run -p enki-app --features nanite` — unplugged from the default in Phase 0 of the voxel migration; still used by the flora Nanite debug view.
- Classic quadtree engine (no voxel/flora/Nanite): `cargo build -p enki-app --no-default-features`.
- Flora (procedural tree) viewer: `cargo run -p enki-app --bin flora_viewer --features flora` — the showcase bin. The planet `enki` bin scatters flora on the surface **only when built `--features flora`** (a `--no-default-features` build never references flora); see the Flora section.
- Vendored C deps: `metis` builds clean on MSVC (no cmake/libclang needed).

All feature configs must always compile — default (`flora,voxel`), `--no-default-features` (classic quadtree), and `--features nanite`.

## Workspace crates

- **enki-rhi** — Vulkan RHI: frame bracket (`begin_frame`/`begin_rendering`/`begin_ui_pass`/`end_frame`),
  pipelines, buffers, descriptors, images, swapchain, the TAA pass (`taa_pass.rs`), the CSM shadow maps (`create_shadow_map`/`begin_shadow_pass`), and whole-frame GPU timing (`gpu_timer.rs` → `Rhi::gpu_time_ms()`; Vulkan timestamp queries, ~FiF stale, off if unsupported).
- **enki-render** — camera, `FrameUniforms`, lights, projection, TAA jitter + resolve (`taa.rs`).
- **enki-planet** — heightfield (tectonic + simple), cube-sphere bases, quadtree LOD (`lod.rs`), mesher, climate/biome coloring, and `vegetation_density()` (the forest field shared by the terrain canopy tint + flora scatter).
- **enki-jobs** — background worker pool for chunk meshing.
- **enki-app** — winit 0.30 app shell, egui panel (`gui.rs`), HUD, `VoxelView` (default terrain) / `PlanetView` (classic quadtree fallback), async startup loader (`loading.rs`), the Nanite integration (opt-in), and the third-person controller + animated `Character` (see below).
- **enki-nanite** — Nanite-style virtualized geometry. **Self-contained, feature-gated (`nanite`, OFF by default), deletable** (see below).
- **enki-flora** — procedural tree generation: a 1:1 Rust port of the `../dryad` JS flora generator (pure gen-core, no Vulkan, golden-gated) + the flora WGSL shaders. Its GPU render path lives in `enki-app` (`flora_*.rs`). **Self-contained, feature-gated (`flora`), deletable** (see the Flora section).
- **enki-voxel** — on-demand voxel/SDF terrain mesher (transvoxel isosurface). Pure mesh-gen (no Vulkan; deps `transvoxel`+`glam`+`enki-planet`); the GPU path is `enki-app/src/voxel_view.rs`. **Self-contained, feature-gated (`voxel`), deletable** (see the Voxel terrain section).

## Core conventions

- **Camera-relative precision:** CPU is f64 (`glam::DVec3`); GPU is f32. The view is rotation-only with the camera at the origin each frame; per-object/per-node translations are f64-subtracted (`origin - camera`) then cast to f32. This keeps planet-scale (radius ~50 km, but coords up to ~6.37e6 in tests) precise.
- **Reversed-Z depth:** `D32_SFLOAT`, compare `GREATER`, clear `0.0`, far plane = depth 0. Sky/cleared depth is 0.
- **WGSL via naga 29:** push constants use `var<immediate>` (NOT `var<push_constant>`); `meta` is a reserved keyword (don't name a binding `meta`). Shaders are **validated by naga inside unit tests** (`cargo test` catches shader errors headlessly — e.g. `shaders_parse_and_validate`).

## enki-nanite (virtualized terrain — opt-in, OFF by default)

**Status:** unplugged from the default build in Phase 0 of the voxel-terrain migration — the default terrain is now `VoxelView`. The crate + `enki-app` integration stay behind `--features nanite` (re-add it to render the planet through the Nanite path, or for the flora Nanite debug view). The architecture below is unchanged when enabled.

**Modularity contract:** ALL Nanite code/types/shaders live in this crate. Lower crates (`enki-rhi`/`-render`/`-planet`) never reference it; `enki-app` is the only consumer, behind `#[cfg(feature = "nanite")]`. Removing Nanite = delete the folder + drop the optional dep/feature + the cfg blocks in `enki-app`.

**Architecture (the "true Nanite" path):**
1. **Bake (offline, at startup):** `bake::tessellate` a heightfield patch (no skirts; analytic face-independent normals) → `cluster_build` meshlets (≤64 verts / ≤128 tris) → `bake::dag` builds a DAG of LOD levels (meshopt simplify + METIS grouping; group **boundaries locked** so the cut is crack-free; monotonic error). `bake_planet` bakes **6 deep per-face DAGs** (res 1024), each with its own f64 `patch_origin`. Held in RAM.
2. **Residency (CPU, `residency.rs`):** `ClusterResidency::select` picks the clusters that should be GPU-resident for the camera — a *superset* of the GPU cut, widened by a margin, **nearest-first** sorted. `ClusterStreamer` wraps it with camera-delta throttling.
3. **Page pool (`render.rs`):** the resident set streams into a **shared, fixed-stride, slot-indexed** GPU pool (`PagePool` from `stream.rs`, timeline-graveyard reuse). `update_residency` uploads only *added* clusters and frees *removed* ones (O(delta), no whole-set re-pack) — this is what makes zoom smooth. Each cluster owns a stable slot; geometry is only ever written to FREE slots (never mid-flight). A per-frame `active_slots` buffer lists the live slots.
4. **GPU cull (`nanite_cull.wgsl`):** one thread per active slot; frustum-cull + the two-sided screen-error cut (`self_px ≤ tau && parent_px > tau`). Appends slots to a `visible` list + advances an indirect draw arg.
5. **Draw (`nanite_draw.wgsl`):** one indirect, non-indexed, vertex-pulling draw; fixed-stride addressing (`slot*MAX_TRIS + tri`, tris store global vertex indices). Per-vertex stride is **20 floats** (pos3+normal3+color3+material1+wetness1+volcanism1+elevation1+plate3+horizon4 — the last is the baked terrain self-shadow, see **Shadows**) — must match `render.rs` `SLOT_FLOATS`. Surface color comes from the unified `view_mode` (see **View modes**); id-based modes key on a **stable id** (`meta.range[3]`), not the buffer slot, so they don't flicker on re-pack.
6. **Popping → dithered LOD cross-fade + TAA:** with TAA on, the cull widens to a transition band (`tau*FADE_HI`); the draw partitions pixels between overlapping LODs by an exact interval `[t_self, t_par)` (no holes/overlap) using a stable per-pixel dither, and TAA resolves the stipple into a smooth blend. Mirrors Unreal's dither+TAA. Gated on `taa_enabled` (off → strict hard cut).

**Gotchas:**
- Descriptor binding stages: the lit fragment reads the `frame` buffer (lights) → its binding needs the `FRAGMENT` stage flag, not just VERTEX/COMPUTE.
- Per-face origins (≤6) drive `node_xlat` (camera-relative translation per face), indexed by `meta.range[2]`.
- The three terrain renderers — `VoxelView` (default), classic `PlanetView` (quadtree), and Nanite (opt-in) — are **mutually exclusive**; exactly one renders the surface at runtime.

## Voxel terrain (default — on-demand transvoxel)

The default surface renderer (feature `voxel`, ON), replacing the Nanite-baked path (Phase 0 unplug). **Self-contained, feature-gated, deletable** — mirrors enki-nanite/enki-flora; off → the app falls back to the classic quadtree `PlanetView`.

- **Density (enki-voxel):** `density(p) = surface_radius(p̂) − |p|` (>0 solid below surface, 0 at surface, <0 air), sampled from the baked `HeightField` in f64 before meshing. **Transvoxel** (Lengyel transition cells) extracts crack-free isosurface meshes; coarser-neighbour leaf boundaries stitch via transition sides. `mesh_leaf(face, level, ix, iy, …, transitions, caves, edits)` returns a `ChunkMeshArrays` (pos/normal/biome-color/plate-color/indices); `mesh_chunk` is the static single-chunk utility. Pure + unit-tested (isosurface accuracy, crack-free seams, dig edits).
- **GPU path (`voxel_view.rs`):** an async quadtree-LOD renderer. `N_WORKERS` background mesher threads turn `MeshReq`→`MeshDone`; a CPU cache decouples "meshed" from "resident" so async latency never blanks the view (a leaf stays drawn until its replacement arrives — no hitch on LOD change / caves / edits). `update` LOD-selects + streams resident leaves to the GPU; `record` draws them; positions are local, drawn camera-relative via `ChunkPush`.
- **Shadows:** casts (`record_shadow`, depth-only per cascade) AND receives the CSM — its lit pipeline is `terrain_csm.wgsl` (own set0: frame UBO + 3 cascade depth maps + comparison sampler), falling back to the shared shadow-less `terrain.wgsl` when no map exists. View modes 0/1/2/6 + geometry-debug 3/4/5 (per-leaf `dbg_id`/level); data modes 7–10 + mode 14 are Nanite-only (the voxel vertex layout has no extra channels).
- **Grounding (single source of truth):** `VoxelView::collider()` → a `SurfaceCollider` (`terrain_grid.rs`) that ray-casts the **actual drawn voxel triangles** (Möller–Trumbore, `GROUND_LEVEL=12`). Character feet + flora ride this; `terrain_grid::ground_radius` (the analytic grid-faceted radius) is the fallback when no leaf is resident along the ray.
- **Caves (WIP):** optional 3-octave-FBM carving below the surface (`CaveParams`: strength/freq/margin/falloff/threshold), seam-safe via the global per-level radial lattice, GUI-toggled in the **Voxel** section. **Edits (WIP):** sphere CSG dig/fill queued per-frame, re-meshing the overlapping leaves on arrival.
- **Remaining (Phase 2+):** per-cascade light-footprint cull for off-screen casters; GPU-compute tessellation for sub-metre close-up detail.

## TAA

`enki-render/taa.rs` (Halton jitter, `ResolveParams`, camera-relative reprojection — the engine renders camera-at-origin, so the resolve bakes the camera-translation delta into the previous view-proj) + `shaders/taa_resolve.wgsl` (depth→world reproject, 3×3 neighborhood clamp, history blend) + `enki-rhi/taa_pass.rs` (MSAA target → resolved current+depth, 2 ping-pong history, resolve pipeline). Toggle in the egui View section — **now default ON** alongside the voxel terrain (see View modes); the frame bracket branches on `taa_active()` so OFF is byte-identical to the non-TAA path. History is 8-bit (swapchain format, for sRGB linear-space blend without duplicating pipelines).

## Shadows (forward renderer)

Two complementary systems — a baked **horizon self-shadow** for large-scale terrain-on-terrain (Nanite path only), and a real **sun shadow map** (3-cascade CSM) for object/contact shadows on every surface. No hardware-RT.

- **Terrain self-shadow — baked horizon map** (Nanite path, `nanite_draw.wgsl::terrain_shadow`): each vertex carries `horizon[4]` = SINE of the max terrain elevation angle in 4 azimuths (`enki_planet::face_bases::horizon_basis` — the single bake↔runtime azimuth contract), baked once in `tessellate.rs`. **Sun-direction-agnostic**, so it works for the moving sun forever. Runtime: reconstruct radial up (`world_rel + cam_world`), compare `sun_elev` to the interpolated horizon, darken the **sun term only**. Subtle by design (mesh-coupled, ~tens–hundreds m; mainly visible at low sun). `horizon[4]` rides the 20-float Nanite vertex stride like the other per-vertex channels. Multiplies in alongside the shadow map (`d0 * terrain_shadow * sample_shadow`). Nanite-only — the voxel/classic terrain has no baked horizon self-shadow.
- **Object shadows — real sun shadow map (3-cascade CSM)**: `D32_SFLOAT` depth maps (default **4096²** each), **`SHADOW_CASCADES = 3` concentric player-centred cascades** (geometric half-extents `base·2^c` → **20/40/80 m** at base 20 m), each **per frame-in-flight** (a shared image would race frame N sampling vs N+1 writing). Flat-stored in the RHI as `shadow_maps[fi*N + c]`. Sampled with **3×3 PCF** (a `GREATER_OR_EQUAL` linear comparison sampler → ~6×6 effective). Casters = terrain (voxel `VoxelView::record_shadow` by default, or Nanite `vs_depth`), the **character** (its own depth pipeline), **nearby trees** (`flora_view::record_shadow_model`, per-cascade radius-gated). Receivers = terrain (voxel `terrain_csm.wgsl::sample_shadow` by default, or Nanite `nanite_draw.wgsl::sample_shadow` in `fs_color` mode 0), the **character** (`character.wgsl` — own set: frame UBO + 3 cascade depth textures + comparison sampler; falls back to the shared terrain pipeline when no map exists), and the **trees** (`flora.wgsl` — set1 extended with cascades 1/2 at bindings 10/11; the planet re-points them at the CSM via `FloraRenderer::set_shadow_cascade_views` and uploads `cascade_mvps` into `ShadowUniforms` with `cascade_count=3, use_view_pos=1`; the viewer keeps its single tree-local cascade). The CSM receiver snippet (`select_cascade`/`sample_shadow`, `textureSampleCompareLevel`, ×2^c bias) is duplicated across the four shaders (`nanite_draw`/`terrain_csm`/`character`/`flora`) — keep them in lockstep. **Supersedes** the screen-space `taa_resolve::sun_shadow` (auto-disabled `ss_shadow = 0` when the map is active). VRAM ≈ `N × size² × 4 × FiF` (3×4096²×2 ≈ **400 MB**); `create_shadow_map` **halves the size on alloc failure** (down to 1024²) so a VRAM-tight GPU degrades to coarser shadows rather than vanishing.
  - **The map IS the generic RHI**: `enki-rhi` gained `create_shadow_map(size, cascades)`/`create_comparison_sampler`/`begin_shadow_pass(fi, cascade)`/`end_shadow_pass(fi, cascade)`/`shadow_cascade_count` + depth-only pipeline variants (`create_graphics_pipeline_pulling_depth` / `create_depth`). So a shadow map on the terrain/Nanite path **is** possible (the old "single-`set0` can't sample a shadow map" caveat only described the *shared convenience* pipeline — Nanite owns its own descriptor set, here extended with bindings **8..8+N = the N cascade depth textures**, binding **8+N = the comparison sampler**, FRAGMENT-only). Flora's raw-ash shadow system was the reference copied from.
  - **Per-cascade caster matrix via push, NOT a frame re-upload.** The N cascade matrices live in `GpuFrameData::light_view_proj_cascades[N]` (`FrameData` mirror, std430 `array<mat4x4,N>`), written once in `update`. The caster runs **one depth pass per cascade**; `vs_depth` picks `light_view_proj_cascades[pc.mode]` via the **push-constant cascade index** (`record_shadow_draw(fi, cascade)`). ⚠️ A tempting "re-upload the single light matrix to the frame buffer per cascade pass" is **WRONG** — all the host-visible writes land before the GPU runs any pass, so every cascade would read the last matrix; push constants are the per-draw mechanism. Character/flora casters bake `lvp·model` into their *own* push, so they just take `cascade_mvps[c]` directly.
  - **Light projection** (`main.rs::sun_light_view_proj` + `sun_cascade_matrices`): per-cascade **reversed-Z ortho** (`enki_render::projection::reversed_z_orthographic`, near→1/far→0, unit-tested) built in **camera-relative** space (same `world - camera` f64→f32 the Nanite draw uses → caster + receiver agree by construction), **centred on the player's feet** in Surface mode (else camera), each **texel-snapped** on the focus point (no crawl while walking).
  - **Receiver** (`sample_shadow` / `select_cascade`): pick the **tightest cascade whose `[0,1]` uv contains the point** (smallest `c`); outside all → lit. PCF samples that cascade's texture via a `switch` (WGSL can't dynamically index separate texture bindings — hence fixed `N`). `depth_bias`/`normal_bias` are **scaled ×2^c** (coarser cascade → bigger texels → more bias). `shadow_params = [depth_bias, normal_bias, strength, enabled]`.
  - **Sharpness = cascade size ÷ resolution.** `texel = 2·half_extent / size`; cascade 0 (±20 m @ 4096²) ≈ **0.0098 m/texel**, c1 ≈ 0.0195, c2 ≈ 0.039 — CSM concentrates texels near the camera. **CSM only wins if each cascade is high-res** — at 2048² the mid/far cascades are *coarser* than a single 4096²/60 m map. Low-sun **grazing** still stretches the footprint by `1/sin(elevation)`. Tunable in **View → Sun shadows** (base radius / depth / biases). **Debug view-mode 14 "Shadow⊙"** tints by selected cascade (c0 red · c1 green · c2 blue · outside black) → concentric rings around the player.
  - **Ceiling (ponytail):** **hard cascade boundary** (no cross-cascade blend → a faint seam at the red→green→blue switch is possible; a blend band is the polish). Per-cascade caster cost is **N× draws** (trees radius-gated *and* now per-cascade light-footprint culled — `frustum_side_planes(lvp)` in `main.rs` — so off-screen trees don't cast; drop tree casting to the near cascades if fps dips). The **terrain** caster (voxel `record_shadow` / Nanite `record_shadow_draw`) reuses the camera-visible set, so off-screen *terrain* casters miss — a sun-frustum cull is the remaining upgrade.

## View modes

A single **`view_mode` (0–14)** drives surface/overlay shading across the render paths (push value: `pc.material_mode` in `terrain.wgsl`, `pc.mode` in `nanite_draw.wgsl`; modes 11–13 are read by the ocean/cloud passes), shown in the egui View section as grouped selectors:
- **View** (shading): 0 Lit · 1 Unlit · 2 Normal · 3 Triangle · 4 Cluster · 5 LOD · **14 Shadow⊙** (debug: selected shadow cascade — c0 red · c1 green · c2 blue · outside black) — 3–5 work on voxel/Nanite (per-leaf/cluster id); 14 Nanite-only; greyed otherwise.
- **Planet** (data): 6 Plate · 7 Height · 8 Material (rock hardness) · 9 Wetness · 10 Volcano (arc/hotspot cones).
- **Ocean** (11 Surface · 12 Intensity) · **Clouds** (13 Density). (keyboard cycle is `% 13` so it only steps 0–12; modes 13 + 14 are GUI-selectable only.)

Data modes read **per-vertex channels** baked at tessellation (`material`/`wetness`/`volcanism`/`elevation`/`plate`), riding alongside `color` through the whole Nanite DAG (cluster→tessellate→dag→cluster_build→`render.rs` vbuf→WGSL pull). Adding a channel = bump the Nanite vertex stride (`render.rs SLOT_FLOATS` + the `base + k` indices in `nanite_draw.wgsl`) in lockstep.

- **Voxel (default renderer) + TAA are default-ON** (`main.rs` AppState). Voxel serves 0/1/2/3/4/5/6 (mode 0 CSM-shadowed via `terrain_csm.wgsl`); data modes 7–10 + mode 14 fall back / are Nanite-only.
- **Nanite (opt-in, `--features nanite`) = full parity** (all 11 modes).
- **Classic quadtree (`PlanetView`, voxel off) = `terrain.wgsl`**: 0/1/2/6 + geometry-debug 3/4/5 (now ported), **no CSM shadows**; Height/Material/Wetness/Volcano still fall back to Lit — **blocked** on the classic vertex layout being hardcoded `4×vec3` in `enki-rhi/src/pipeline.rs` (shared by 6 pipelines; a 5th data channel needs an optional `vec4` binding gated by a `GraphicsPipelineDesc` flag). Low priority.

## Ocean (FFT waves + foam + refraction)

A **refractive ocean** in `enki-app/src/ocean/`. With TAA on, `WaveSurface` draws the whole ocean as one refractive 1× pass — a Tessendorf-style **multi-cascade spectral FFT** surface on a projected grid (see below). With TAA off, the old `Ocean` (alpha-blended MSAA shell sphere) is the fallback.
- **`WaveSurface`** — the projected-grid FFT ocean (covers near field + horizon, no patch/shell).
- **`Ocean`** — a smooth translucent sea-level shell sphere, **TAA-off fallback only**.

**Sim (CPU, `ocean/{fft,spectrum,sim}.rs`):** JONSWAP×TMA×Donelan spectrum → `h0(k)` → time-evolve → inverse FFT → displacement (xyz, choppy) + slope normals + **Jacobian foam**. **3 cascades at poseidon's N=256, tiles [250,17,5] m** (→ cm-scale ripples). FFT is **`rustfft`** (the hand-rolled radix-2 only did N≤64). Too heavy for the render thread, so the sim runs on a **background worker** (`std::thread`) that double-buffers its latest field into a `Mutex<Vec<OceanTexel>>`; `record` uploads that to the GPU each frame and the worker idles when no waves are drawn. ponytail: GPU compute is still the eventual upgrade (enki-rhi has compute + storage buffers), but the worker keeps it 60 fps now.

**Wave mesh — projected grid (`ocean/mesh.rs`):** the wave geometry is a **screen-space lattice** (`ndc_grid`, `PROJ_RES`) whose vertices are ray-cast onto the sea sphere every frame on the CPU in f64 (`project_to_sphere`; misses snap to the limb silhouette) into a per-FiF dynamic vertex buffer, drawn by `vs_projected`. It fills the whole view — near field **and** horizon — with **no patch and no shell** (the projected grid IS the entire ocean), and the cells are ~screen-uniform so density follows perspective for free. `mesh.rs` has the two generators + ray/sphere projection unit tests. (Earlier warped-patch + clipmap-ring modes were removed — mesh density only moves vertex *displacement*, which is invisible vs the per-pixel normals; the projected grid is the only one that changed what you see by fixing the patch boundary.)

**Surface (`shaders/ocean_surface.wgsl`):** `vs_projected` builds each vertex's frame from the sphere normal (`center_rel` = planet centre − camera) + the sub-point tangent (for FFT sampling), FFT-displaces, and `fs_main` shades; camera-relative + reversed-Z. **Tile blending (`sample_blend`)** breaks the FFT tile repeat: each ~`BLEND_M`-sized cell rotates+offsets the sample coord and 4 cells are bilinearly blended (horizontal vectors rotated back into the grid frame), so no region reads as a single repeating tile and the rotations look like **crossing / multi-directional seas** — this replaced the old (too-low-freq) domain warp. **Wind-driven** height + intensity: the planet's baked wind (`HeightField::wind_speed_at` → `Climate::wind_speed_at`) is sampled per projected vertex on the CPU each frame into a storage buffer (binding 6), read by `vs_projected` via `vertex_index`, passed to the fragment — so wave amplitude/roughness/foam follow real wind (and the "Ocean → Intensity" heat-map shows it). The wind source is set on the ocean once the heightfield finishes loading (neutral 0.5 until then). **Distance LOD**: a per-pixel screen footprint (`fwidth(world_pos)`) fades each cascade's foam + normals where the pixel can't resolve them, and roughens the specular sun disc with distance — so far / zoomed-out water doesn't alias into white speckle (foam near-field only). Custom set 0 (frame UBO + field storage + ocean UBO + scene **color** + scene **depth** + per-vertex **wind**). Shading = Fresnel sky reflection + sun glint + SSS + foam + **depth-based absorption** (deeper column → darker, projected toward vertical so it tracks ocean *depth*, not view angle).

**Refraction + depth (TAA path only):** `rhi.begin_water_pass()` splits the 3D pass — closes the opaque MSAA instance (resolving to the TAA `current` image + `resolved_depth`), blits opaque color into a history scratch (refraction source) **and copies `resolved_depth`→`refract_depth`** (the depth source for darkening), then reopens a **1× instance on `current`** the water draws into (blend on, alpha 1 → opaque, depth-write off). Requires TAA on; with TAA off only the fallback shell shows. Reuses TAA's `current`/history (no new color image) — `taa_resolve` runs unchanged.

**Gotchas:** the projected `ndc_grid` is wound so cull-BACK keeps the camera-facing face (its triangle normal `rgt×up = −fwd` points at the camera, like the terrain's `east×north = up`); the projection's `-f` Y-flip makes world-CCW front-facing. Graphics pipelines with no push constants pass `push_constant_size: 0`. GUI: Ocean section (toggles + sea-level / choppiness / foam) + view-mode rows **View / Planet / Ocean / Clouds** (Ocean 11 Surface, 12 Intensity; Clouds 13 Density).

## Wind streaks + atmosphere + clouds + reference markers

Several thin overlay layers in `enki-app`, drawn over the planet (Planet mode). The wind/atmosphere/marker/river layers reuse the standard `set0` (FrameUniforms) + `ChunkPush` and the hardcoded 4×vec3 vertex layout — **none touch the shared terrain path**; each naga-validates its WGSL in `cargo test -p enki-app`. (Clouds is a heavier fullscreen raymarch with its own pass — see its bullet.) GUI: **Wind / Atmosphere / Clouds / Reference** sections.

- **Wind streaklines (`src/wind/`)** — a "living" flow viz of the planet's baked wind field (NOT clouds; debug-grade). `sim.rs` (pure, headless, unit-tested) advects a fixed particle pool through `HeightField::wind_at` — the baked **unit-tangent velocity + speed** cubemap (`Climate::wind_at`, newly exposed on the trait; `WindSample` is world-space xyz, zero at poles) — on a cap around the sub-camera point, plus a cheap time-varying **gust** (rotate the wind about the local normal — no fluid solver; this is Tier B, not Navier–Stokes). Each particle keeps a short trail → a **camera-facing ribbon** (constant screen width), colored blue→white by speed, faded head→tail + birth/death. `mod.rs` owns the GPU glue (per-FiF dynamic vertex buffers; pos in slot 0, packed `[fade, speed, 0]` in the color slot; fragment ramps + alpha). Ribbons are **double-sided** (both index windings — the shared pipeline culls BACK and these are billboards). Drawn **after the ocean** (streaks ride ~1.5 km up = top layer, so the opaque sea can't paint over them); `WindOverlay` holds **two pipelines (MSAA + 1×)** and picks by whether `begin_water_pass` split the frame.
- **Atmosphere — two systems, mutually exclusive by TAA:**
  - **Aerial scattering (`aerial.rs` + `.wgsl`, the real one, TAA-ON):** a fullscreen depth-aware Rayleigh pass in the water split — reads the opaque scene depth, integrates a closed-form thin-slab in-scatter along each camera→surface ray (Chapman air-mass march, day-side gated), composited as `inscatter + background·transmittance`. Does what a shell can't: distance-graded aerial perspective on terrain/sea from orbit **and** the overhead sky dome + limb halo from the surface. **This dome IS the surface sky** — there is no separate sky pass (`SkyModel` is lighting/time only, never drawn), so it sits over the near-black clear `[0.02,0.03,0.05]` and `sky_strength` (sky-pixel-only multiplier) must carry real brightness or the sky reads dark. GUI **Aerial** section (Top/Falloff/β/Intensity/Sky brightness); all USER-tuned live.
  - **Atmosphere shell (`atmosphere.rs` + `.wgsl`, TAA-OFF fallback only):** one translucent sphere at `R + height`, analytic limb-dense alpha + day/night + sunward glow; alpha + air-mass gated by `abs(viewDir·nFrag)` and the limb `glow` so the near disc stays see-through from orbit (else it veils the planet). Drawn in the opaque pass **only when `!(taa_enabled && aerial_enabled)`** — under TAA the aerial pass supersedes it (drawing both double-tints the planet blue). Density via a `ChunkPush` pad slot; GUI **Atmosphere** section. **ponytail: both are analytic, NOT real Rayleigh/Mie multi-scatter.** Upgrade = port ki `Atmosphere.ts`.
- **Reference markers (`markers.rs` + `.wgsl`)** — toggleable equator ring (green) + N/S pole spikes (red/blue), camera-facing ribbons. **Opaque (`blend:false` → depth-write ON)** so the water pass depth-tests them away and they show through the sea. Default off.
- **River network (`rivers.rs` + `.wgsl`)** — a drainage water-surface extracted from the baked erosion flow field as a **junction-node GRAPH** (Peytavie 2019 / Génevaux 2013; see `docs/rivers-research.md`). Three stages on a cube-sphere grid at the erosion res (256): (1) threshold the **UNblurred** discharge `flow_accum_sharp_at` into a channel raster — the *blurred* `flow_accum` smears channel peaks into fat gradients, so an earlier streamline-trace attempt flooded the basin (blobby/stippled); (2) give each channel cell one downstream pointer (flow-aligned 8-neighbour) + count in-degree; (3) walk one reach from every NODE (source = in-degree 0, confluence = in-degree ≥2) to the next node/outlet, Catmull-Rom-smooth, sweep a ribbon with half-width ∝ √discharge. Each reach is traced ONCE — no merge-stubs, no flood. Reads `HeightField::{flow_accum_sharp_at,flow_dir_at,lake_mask_at,height}` (TectonicHeightField delegates to `Erosion`; `Erosion` keeps an unblurred `flow_accum_sharp` copy alongside the blurred one — additive, no height-golden impact) + the `cubemap` helpers; the extractor is pure/headless (unit-tested). **Translucent (`blend:true` → depth-write OFF, depth-test GREATER)**, drawn after markers in the opaque MSAA instance — rivers ride on LAND (above sea level), so the later ocean pass never paints over them. Built ONCE when the heightfield arrives (`set_source` → lazy build in the first `record`); only the camera-relative position buffer is rewritten per frame (mirrors `markers.rs`); shares markers' `overlay_pipeline`/`draw_ribbon`. Default ON; GUI toggle in the **Reference** section. Density knob = `CHANNEL_THRESHOLD` (on the sharp field). **Follow-ups:** slope-area channel-initiation (`A·Sᵏ`) + Strahler-order pruning for finer control; lake *surfaces* (the walk terminates AT lakes but doesn't fill them); flow-aligned animated water (blend-flow / scrolling normals).
- **Volumetric clouds (`clouds.rs` + `clouds.wgsl` + `clouds_advect.rs`)** — a fullscreen raymarch of a spherical cloud shell whose coverage is **advected by the baked wind**. A background worker (`CloudAdvect`, modeled on the ocean sim worker) semi-Lagrangian-advects a coarse equirect coverage grid along `wind_at` each tick (re-forms toward the climate moisture field at `form_rate`, decays at `decay_rate`); the render thread copies the grid into a per-FiF storage buffer the shader samples (the shader no longer warps noise by `wind×time` — it just reads coverage). Analytic in-shader noise + coarse coverage grid because **enki-rhi can't upload a 3D texture** (the storage-buffer-+-analytic-shader pattern). Drawn **inside the ocean's refraction split** (the reopened 1× instance) so it composites over the resolved opaque scene and samples its depth for terrain occlusion → **TAA-on only**. Knobs (coverage/density/altitude/thickness/type/HG/powder/curl/steps + advect form/decay) in the **Clouds** GUI section; view-mode **13 Density** shows the coverage field. Default ON. See `docs/clouds-advection-research.md`.

**Draw order (Planet mode):** **sun shadow caster pass** (depth-only, in the `begin_frame`→`begin_rendering` gap: terrain + character + nearby trees → the shadow map) → voxel terrain → bodies → atmosphere → markers → **rivers** → character/trees → ocean → **clouds** → **wind (top)**.

**Gotcha — why overlays vanished over water at first:** a translucent overlay drawn *before* the opaque ocean with depth-write OFF gets painted over wherever there's sea (fine over land). Fixes: opaque markers **write depth** (water depth-tests them away); translucent wind **draws after** the water (top layer). The reopened water instance LOADs the resolved opaque depth (`begin_water_pass`), so depth-writing in the opaque pass is what occludes the sea.

## Third-person controller + character

A surface controller with an animated character. Lives in `enki-app` (`controls/third_person.rs` + `character.rs`); nothing below `enki-app` references it.

**Nav modes (`controls/nav_mode.rs`):** `Globe → Placement → Surface → Globe`. `Surface` (renamed from the old `FirstPerson`) hosts the `ThirdPersonController`; it has a **1st/3rd-person view toggle** (V), so a single mode/controller serves both. The standalone `FirstPersonController` is **no longer wired** but kept for its tests + the shared grounding helpers — don't delete it without moving those. Spawn = the existing `Tab → Placement → click` ray-cast.

**`ThirdPersonController`:** headless (no winit/GPU, fully unit-tested). Feet ride the **rendered** surface via `VoxelView::collider()` — a `SurfaceCollider` (`terrain_grid.rs`) that ray-casts the **actual drawn voxel triangles** under the feet (Möller–Trumbore, `GROUND_LEVEL=12`) — NOT the analytic `first_person::surface_radius`, which carries sub-cell octave detail the mesh never draws so a point-sample of it sinks into bumps that aren't there. This collider is **the single source of truth for grounding** — character feet + trees ride it; `terrain_grid::ground_radius` (the analytic grid-faceted radius) is the fallback when no leaf is resident, and `surface_radius` is demoted to a generator/probe (do NOT ground on it). Movement is **camera-relative WASD**; the body yaws toward its travel direction. Mouse orbits the chase cam (`cam_dir`/`cam_pitch`), scroll sets the boom (`cam_dist`), and an **8-step occlusion march** pulls the boom in so the camera never clips terrain. `camera()` branches on the view: third = boom behind a shoulder anchor; first = at the eye (caller hides the mesh).

**`Character` (CPU skinning):** an ~11-bone box humanoid built procedurally (`build_rig`); a hierarchical gait solver (`solve_pose`, mirrors the flora wind-solver shape) swings legs/arms in anti-phase scaled by speed, with idle breathing. **Skinned on the CPU** (one bone/vertex) into a **per-frame-in-flight pos/nrm vertex-buffer ring** (`write_storage_bytes` each frame; mirrors flora's `bone_ubos` ring so writing this frame never races the GPU reading last frame's), then drawn with the **existing terrain pipeline** (`material_mode 0`) via `ChunkPush::camera_relative`. Rest pose at `speed==0 && phase==0` is an exact standing figure.
- ponytail: **CPU skin + terrain pipeline** — no skinning shader, no custom descriptor set, no extra vertex channel. One low-poly character is trivial to re-skin per frame; move to the GPU/flora skinning path only when there's a crowd. glTF import + 4-weight skinning is the other upgrade path (the rig generalizes to it).

**Gotchas:**
- Character verts are in **local character space** (feet at origin, +Y up, +Z facing); planet placement is the draw's model matrix `from_cols(right, up, forward, _)` with `right = up × forward` (det +1 → CCW winding preserved for cull-BACK). Boxes are wound CCW outward in `push_box`.
- Drawn **after the terrain, before the ocean**, inside the opaque MSAA instance; only when `nav == Surface` and the view is third-person. `Character::update` (skin + upload) runs *before* `begin_rendering` (it's a host-visible memcpy, fine either side); `draw` runs inside.
- `Character::new` (built at startup in Planet mode) clones the terrain pipeline desc byte-for-byte, so it inherits reversed-Z / MSAA / swapchain format with no special-casing.
- Controls: Tab → click to drop · WASD (camera-relative) · Shift sprint · mouse orbit · scroll zoom · **V** 1st/3rd · Esc → orbit.

## Flora (procedural trees — `enki-flora` + `flora_viewer`)

A **1:1 Rust/Vulkan port of the `../dryad` JS flora generator** (procedural trees), shown in a standalone CAS-style viewer. **Self-contained, feature-gated (`flora`), deletable**: the pure generator is `enki-flora`; ALL GPU glue is in `enki-app` behind `#[cfg(feature="flora")]` (`flora_render.rs`/`flora_view.rs`/`flora_ibl.rs`/`flora_nanite.rs`/`bark_swatch.rs` + `src/bin/flora_viewer.rs`); the default build never references it. `enki-app` is `lib + bin` so the `flora_viewer` bin can share `flora_view` via the lib.

**Two halves, meeting at `resolve(&Genome, &Env)`:**
- **Gen-core (`enki-flora/src`, pure, NO Vulkan, deterministic):** `rng` (mulberry32) → `genome` (`random_genome`/`resolve`) → `skeleton`→`roots`→`proportions`→`foliage`, plus `leaf_texture`/`wind_solver`/`mesh`/`bark_swatch`/`color`/`allometry`. A faithful port of dryad's; **determinism is load-bearing** (see the golden contract below).
- **Render (flora-OWNED raw-`ash` sub-renderer, `flora_render.rs` + `enki-flora/shaders/{flora,staging,post}.wgsl`):** modeled on the egui renderer — flora owns its own VkPipelines + descriptor **set0**(FrameUniforms)/**set1**(shadow map + IBL + wind bone buffer + leaf textures) + its own `gpu-allocator` + offscreen targets, recorded into the viewer's frame bracket. enki-rhi's constrained `create_graphics_pipeline` (one hardcoded set/layout) is bypassed for flora's multi-set needs; the **shared rhi/terrain path is untouched**.

**Render pipeline is 1:1 with dryad:** Cook-Torrance PBR (`pbr_shade`) bark/leaf/ground; HDRI IBL (SH9 irradiance + roughness-mip equirect specular baked from `enki-app/assets/flora/kloofendal_43d_clear_1k.hdr`, embedded via `include_bytes!`, in `flora_ibl.rs`); **PCF sun shadow map** (the tree self-shadows — bark+leaf sample it); dryad light rig (sun `#fff4e0`×3.0, hemi×0.3, env 0.6, exposure 1.0) + Preetham sky (`staging.wgsl`); UnrealBloom → **single ACES** in the composite (linear-HDR offscreen intermediate, no double-tonemap, `post.wgsl`).

**Leaves:** baked superformula+venation textures (`leaf_texture.rs`, color + Sobel-normal, per-genome) on **base-anchored 6-segment curved strips** that grow OUTWARD from the twig (base→tip length axis = the cluster tangent, NOT up) and **droop** (t² world-down × `LEAF_BEND` 0.45). Modes: `Cluster` (1 card = the 5–8-leaf sprite, default) / `Single` (1 card = 1 leaf, `bake_leaf_single`). Single-plane, **double-sided** (back-face normal flip → thin edge-on; dryad's crossed-card multi-plane mode is NOT ported). Render-side **twigs-only** gate; the fine twig wood is **tapered** toward the tip (rendered thin, not deleted) so leaves attach without bare sticks poking. Render-side `LeafTuning` sliders (insertion / up-bias / droop / size / density) live in the View panel and are **golden-free**. **Leaves shade FLAT + MATTE:** by their own geometric card normal (the canopy sphere-normal *volume* shading was removed), with NO canopy-depth darkening (the height/level `exposure` dimming was removed — bottom/interior leaves are no longer darkened), and **pure diffuse** (`pbr_shade` `spec_scale = 0`: no GGX highlight, no IBL sky reflection, no Fresnel rim). The canopy varies only by real sun dir + PCF shadows + per-leaf jitter.

**Bark:** procedural in-shader (no baked texture — only leaves are textured) — **furrow-guided ridged-FBM** (replaced dryad's older voronoi-plate model). Flow-line furrows run UP the branch axis, guided by a carried **parallel-transport frame** (per-vertex `aTangent`+`aFrameU`, baked by the mesher and **INHERITED across forks**) + a **global arc** UV (continuous across junctions), so the bark is **seamless on every axis**: cylinder-embed around, carried frame across forks, global arc along. The around-the-branch angle = `radial normal · frame` (NOT `uv.x` → no wrap seam). Furrow walls + horizontal cross-cracks (oak scales) drive an analytic **view-space normal**; **crack-AO** darkens the fissures; the albedo is a flat base + furrow/ridge colour split (the *pattern* lives in the normal, not the albedo). A uniform per-material **exposure trim** (`×(0.50,0.44,0.38)`) lands enki's sun×3+IBL bark on dryad's warm brown (calibration knob — dryad's three.js ACES doesn't need it). The branch **lit pipeline is 6-stream** (pos/nrm/uv/attr + aTangent/aFrameU; `Rhi::bind_vertex_buffers_slice`); the depth caster stays 4-stream. **Fork-seam fix:** the shared fork ring uses the parent's frame AS-IS (the bend is absorbed by the next-ring transport) — pre-transporting it, as dryad does, left a horizontal furrow seam at every junction.

**Wind:** hierarchical bone-skinned (ported `windSolver`+`windSkinGlsl`) — the mesher bakes per-vertex bone weights + a `bones_wind` hierarchy, a per-frame Rust solver composes per-bone matrices → set1 storage buffer → vertex skinning. The leaf gust is **coherent along `windDir`** (not random per-leaf tumble), with an **editable arrow gizmo** at the base (drag on the ground plane to set wind direction). `strength=0` = byte-identical static.

**UI:** egui "flora · CAS" panel — left: preset header + tab strip **Climate/Trunk/Branches/Leaves/Root** (dryad's gene grouping); top-left View window: render modes + Wind + Bloom + Leaf-placement + **Dappled shadows** toggles; top-right Stats. Plus a debug **Inspector** dock (leaf texture/normal/shape, pigment swatch+ramp, bark swatch (CPU-approx of `barkAlbedo`), cross-section). Render modes include **Nanite Triangle/Cluster/LOD**: the branch mesh is baked into `enki-nanite` clusters (`flora_nanite.rs`, via `build_base_clusters`+`build_dag` — the arbitrary-mesh path) and drawn through the Nanite cull+draw, leaves hidden in those debug views.

**Dappled shadows** (View toggle / `FLORA_DAPPLED`): bumps the shadow map to 4096² and a `dappled` flag (`ShadowUniforms.params.w`) lets the real self-shadow dominate → sun-through-canopy. (It used to also soften the canopy-sphere-normal + exposure "fake", but that fake was since removed — leaves are flat-shaded now — so dappled purely adds high-res shadow detail.) Pure per-frame uniform, no rebuild.

**Determinism / golden contract:** `enki-flora/tests/golden.rs` (`golden_vector_matches_dryad`) byte-compares `resolve()`'s foliage (count/position/scale/rotation/shape) against a dryad-JS dump (`tools/dump_golden.mjs` imports the real `../dryad` JS → `tests/golden.json`). Bar: rng draws + genes EXACT (1e-12), geometry 1e-6 (cross-language trig ~1 ULP). **NEVER reorder genome rng draws (incl. the RESERVED no-ops) or edit `foliage.rs`/`skeleton.rs` placement math / `GOLDEN_ANGLE` without a flag-gated path** — it breaks golden. Mesh changes go through `seed_42_mesh*` determinism tests (NOT loosened). ALL render-side work (`flora_view::build_leaf_mesh`, the shaders, `LeafTuning`, the twig taper) is golden-free. naga + a spv-out emit test validate every WGSL in `cargo test`. NOTE: dryad `resolve(genome, {})` yields NaN (no `gravity` default) — always pass an explicit neutral `Env::default()`.

**Phyllotaxis:** the leaf-cluster azimuth is a 1:1 port — `az_step = (1-radialOrder)·π + radialOrder·GOLDEN_ANGLE` (`GOLDEN_ANGLE = π(3−√5) ≈ 137.5°`). Gene-gated by `radialOrder`; the default broadleaf (`≈0.25`) blends toward alternating (180°), so set `radialOrder=1.0` for the visible golden-angle spiral.

**On the planet (`--features flora`):** `flora_scatter` **deterministically** scatters trees on the surface — a tree's existence/position/yaw/scale is a pure hash of its lat-lon cell, so walking never reshuffles the grove (only the visible window slides); the set is rebuilt only when the player crosses ~½ a cell (`SPACING_M`) or the radius/density changes. Where trees grow is gated by `enki_planet::vegetation_density()` — the **same forest field that tints the terrain canopy green**, so scatter and the baked tint agree (this replaced the old local grove-FBM). Every instance is the ONE shared species mesh (`TreeSpec::default_specimen` genome, overridden to **`Single`**-card leaves for the planet — the viewer default stays `Cluster`). **Distance LOD is now ON for the scatter:** full geometry within `TREE_GEOM_M` (40 m) via `record_at_lod`, crossfading over `TREE_FADE_M` (25 m) to a baked green-disc **impostor billboard** (`record_impostor_at`, TOP/SIDE atlas from `bake_impostor`); pure impostor beyond, out to the window radius `RADIUS_M` (250 m default, GUI-tunable 100–2000 m). `MAX_TREES` (16000) is a **hang-guard, not a per-frame LOD cull** — it only trips on a pathological density×radius, dropping the FARTHEST + `warn!` (never a silent cull). **ponytail: scattered trees are plain per-instance flora draws, NOT Nanite-virtualized**, so geometry draw cost scales linearly with the in-window count; a planet-scale forest — or a wider geometry radius without an fps cliff — would need the trees baked into the Nanite path (`flora_nanite`'s single-tree branch bake is the seed of that). The scatter draw + tree shadow casters **are** frustum-culled (camera side-planes + a behind-camera dot for the draw; per-cascade light-box footprint for casters — `frustum_side_planes`/`sphere_in_side_planes` in `main.rs`, sphere radius via `FloraView::cull_radius`). **Grounding:** every instance rides the voxel `SurfaceCollider` (see Third-person) — the same rendered-triangle surface the character's feet use — NOT the analytic `surface_radius` (objects sink into sub-cell detail the mesh never draws). Drawn in the opaque pass after the character, before the ocean; GUI **Trees** section (toggle + density + **Tree radius** slider).

**Visual correctness is USER-verified** (headless agents can't see pixels). For render work: capture a PNG via `FLORA_SCREENSHOT` and LOOK at it — compile/naga/Vulkan-validation green ≠ visually correct (the first 1:1 build rendered a black void with a bloom-blown canopy and still passed every gate).

## Terrain ↔ ki parity (determinism gate)

The landmass (tectonics + heightFn + rockHardness + cube-sphere) is a faithful port of **ki** ("Demiurge", a TS/WebGPU sibling at `../ki`). `enki-planet/tests/determinism.rs` gates it against `tests/goldens/golden.json`.
- **`golden.json` is dumped from ki itself** — `cd ../ki && npx -y tsx tools/dump-golden.mjs` (imports ki's modules at their native config; writes to enki's golden path). `noise`/`fbm`/`ridged`/`tectonics` are ki-sourced byte gates (1e-9); `height` is an enki self-snapshot (enki ships a B-path erosion the dump tool doesn't run) — regen after a *reviewed* height change via `cargo test -p enki-planet --test determinism -- --ignored regen_golden_height_samples`.
- **Tectonics bakes at `RES=512`** (`tectonics.rs`) to match ki seed-for-seed — the crack/arc bands are absolute radians, so a smaller RES bakes a *different* set of continents. Was 256; **do not revert.** enki matches ki on **28/30 tectonic samples byte-exact**; the gate carves out conv/shear at the exact poles (`degenerate_pole`) — gradient-derived (`t_hat = −∇dist/|∇dist|`) and irreducibly amplified across JS↔Rust float at the near-zero-gradient singularity, NOT an algorithm divergence.
- **Cost:** RES=512 makes the tectonics bake ~4× heavier (~18s debug / ~1–3s release, async on the loader thread) — a slow first-load is expected.
